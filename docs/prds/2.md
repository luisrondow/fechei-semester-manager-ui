# Product Requirements Document - PostMVP Features

## 1) Overview
This release adds three capabilities: (1) a single “current semester” defined by date range with automatic archiving + an Archive page, (2) a per‑subject spaced‑repetition planner generated from PUC topics/calendarization, and (3) grade tracking that includes “teacher grade submission due dates” and dashboard alerts when grading is overdue.  
The system continues to derive structure from common PUC sections (topics/roteiro, evaluation calendar, work plan/calendarization, resources) when present.

**Audience:** Any university student (no tiers).  
**Platforms:** Web (internal calendar UI + export only; no notifications in this release).

---

## 2) Goals & non‑goals

### Goals
- Keep the dashboard focused on the active semester while preserving past semesters for reference.  
- Provide a lightweight per‑subject study cadence that improves completion rate and reduces planning effort.  
- Make assessment and grading timelines visible in one place (submission + expected grading date + actual release date).  

### Non‑goals (v1)
- Teacher/LMS integrations (e.g., automatic grade pulls).  
- Group sharing / collaborative semesters.  
- Cross-term courses/exams after semester end (explicitly out of scope).  
- “Exam cram mode” (possible later).

---

## 3) Feature requirements

### A) Current semester + archive

#### A1. Semester definition
- A semester has a required `start_date` and `end_date` (date range).
- Exactly one “current semester”:
  - If `today ∈ [start_date, end_date]`, that semester is current.
  - If none match, the dashboard shows an empty state: “No current semester” with a CTA to create one.
  - If multiple overlap, select the semester with the latest `start_date` as current and show a warning banner.

#### A2. Auto‑archive
- A semester is auto‑archived when `today > end_date` (user timezone).
- Archive behavior:
  - Archived semesters are **read-only**.
  - Archived semesters are hidden from the dashboard and “current semester” flows.
  - All data remains stored: PUC files, extracted structures, events, edits, user-saved resources, grades.

#### A3. Archive page
- Provide an Archive page listing archived semesters.
- Selecting an archived semester opens the same experience in read-only mode.
- No restore/unarchive in this release.

#### A4. Acceptance criteria
- When the date passes `end_date`, the semester disappears from the dashboard and appears in Archive with all data intact.
- Archived content cannot be edited; UI clearly indicates read-only mode.

---

### B) Spaced‑repetition study planner (SM‑2 style)

#### B1. Outcomes & UX
- Output is a per‑subject schedule (week view) of suggested study sessions.
- The plan is **suggested but editable**:
  - Users can move sessions to other days (edit/drag).
  - Users can set per‑subject weights to allocate time.

#### B2. Inputs
- Seed study items automatically from PUC topics/themes (e.g., “Tema 1…Tema N”) and map them to the semester timeline using PUC calendarization/work plan when available.
- Users configure weekly availability (minutes per weekday) and optional “no study” days.
- The planner does **not** auto-adapt on missed days (missed sessions go to a backlog view; user decides what to do).

#### B3. Algorithm & scheduling rules
- Use an SM‑2 style algorithm with an easiness factor and intervals updated after each review; SM‑2 is commonly described with an initial easiness factor (e.g., 2.5), interval progression, and easiness factor adjustment based on recall quality.
- Ratings: “Again / Hard / Good / Easy” drive the recall quality input (implementation must be consistent and documented).
- Capacity handling: if a day is full, sessions **push forward** to the next day with available capacity (no compression).

#### B4. Scope limits
- Only “study” sessions (no practice problem scheduling in this release).
- No exam cram mode in this release.

#### B5. Empty states
- If PUC calendarization is missing, generate a generic cadence across the semester range and label it “low confidence.”
- If topics/themes cannot be detected, show an empty state: “No topics detected. Add topics manually to use the planner.”

#### B6. Acceptance criteria
- After uploading a PUC with detectable themes/topics, the system creates study items per theme and generates a weekly schedule per subject.
- Completing a review with “Again/Hard/Good/Easy” updates the study item’s next due date using SM‑2 style state.
- When a day is at capacity, additional sessions move to the next available day.

---

### C) Grade tracking + teacher grade submission due dates

#### C1. Settings
- Users define grade preferences in Settings (grade scale, passing threshold, optional rounding rules).
- Grades are personal only (no sharing, no audit history in this release).

#### C2. Assessment timeline fields
Each assessment event supports:
- Student submission due date (already exists).
- Teacher grade-submission due date (new).
- Grade release date (optional actual date).

Source rules:
- If the PUC provides relevant dates, import them; otherwise leave empty and allow user entry.

#### C3. Computation & alerts
- Users enter grades per assessment; system computes:
  - Current grade (based on graded items).
  - Required grade on remaining assessments to reach passing threshold.
- Dashboard alert:
  - If `today > teacher_grade_due_date` and grade is empty, show an “Overdue grade” alert linking to the assessment.

#### C4. Acceptance criteria
- User can enter grades and see computed current + required grade values.
- If teacher grade due date passes with no grade entered, dashboard shows an “Overdue grade” alert.

## 4) Data model (minimal)

### Core entities
- `Semester(id, user_id, start_date, end_date, archived_at nullable)`
- `Subject(id, semester_id, name, weight default 1.0)`
- `PUCDocument(id, subject_id, file_ref, extracted_text_ref, parsed_json_ref, language)`
- `Event(id, subject_id, type {study_block, assessment, study_session}, start_dt, end_dt, title, notes, source_ref, is_confirmed)`

### Study planner
- `StudyItem(id, subject_id, title, source_topic_ref, ef, interval_days, repetitions, next_due_dt)`
- `StudyReview(id, study_item_id, reviewed_at, rating {again, hard, good, easy}, resulting_next_due_dt)`
- `Availability(user_id, weekday, minutes_available)`
- `SubjectWeight(subject_id, weight)`

### Grades
- `GradeSettings(user_id, scale_type, passing_threshold, rounding_mode, missing_grade_policy)`
- `AssessmentGrade(event_id, grade_value nullable, max_value nullable, teacher_grade_due_dt nullable, grade_release_dt nullable)`

### Resources (existing)
- `SavedResource(id, user_id, subject_id, title, url, notes, tags[], pinned)` (remains available; read-only in archived semesters)

---

## 5) Calendar export (unchanged contract)
- Export internal calendar to iCalendar (.ics) in two modes:
  - Full calendar (study blocks + assessments + study sessions if desired).
  - Due-dates-only (assessments + deadlines only).
- Use VEVENT with stable UID and DTSTART/DTEND semantics per iCalendar spec (DTEND is non-inclusive).

---

## 6) Open decisions (must finalize during implementation)
- Overlapping semester ranges: current selection rule is “latest start_date wins + warning banner.”
- Completion rate definition for the planner: recommend “% of scheduled sessions completed within 24h of due date” (confirm window).
- “Missing grade policy” default: exclude ungraded assessments from current-grade computation (confirm default).
